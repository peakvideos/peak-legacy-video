# Build Order

High-level phases for the Peak Studios CO inbound sales system. Each phase will be broken into a more detailed prompt before execution.

## Confirmed decisions

- **Framework:** Next.js (with the breaking-changes caveat in `AGENTS.md` — read `node_modules/next/dist/docs/` before writing Next.js APIs)
- **Auth:** BetterAuth, scoped to the owner's CRM only. No public lead accounts.
- **DB:** Postgres on Railway, Drizzle ORM
- **Hosting:** Vercel (web) + Railway (Postgres)
- **UI:** shadcn/ui + Tailwind, TypeScript
- **Transactional email:** Gmail SMTP via nodemailer (App Password auth)
- **Landing page nav:** none (per PDF spec). Logo lives in hero top-left. When spec and mockup conflict, spec wins; when spec is silent, mockup wins.
- **FAQ:** keep on landing page (between About and Footer CTA)
- **Booking flow:** modal on the landing page, 3 steps + confirmation screen
- **Payments:** out of scope. Owner sends Wave link manually post-call.

## Phase 0 — Project foundations

Set up everything we need before writing features.

- Tailwind tokens for the brand palette (`forest`, `forest-deep`, `gold`, `gold-light`, `moss`, `blush`, `tofino`, `sky`, `sky-light`, `off-white`)
- Google Fonts: Alata (headings) + Cardo (body) wired through `next/font`
- `globals.css` set up (already partially modified per git status)
- Install shadcn primitives we'll use (Dialog, Button, Input, Textarea, Select, Calendar, Checkbox, Form, Sonner/Toast)
- Drizzle config + Railway Postgres connection string in `.env`
- BetterAuth installed but not yet wired (we'll wire it in Phase 5)

## Phase 1 — Database schema

Drizzle schema for everything we'll need. Migrations runnable.

- `leads` — lead form submissions; tracks every form submit
  - id, first_name, last_name, email, phone, package_interest, notes, source, utm_*, booking_status, created_at
- `bookings` — created when a lead picks a slot
  - id, lead_id, scheduled_at (timestamptz), gcal_event_id, status, created_at
- `email_jobs` — queue for the 5-email follow-up sequence
  - id, lead_id, sequence_step, send_at, sent_at, status, last_error
- `users` — for BetterAuth (owner only)
- BetterAuth's required tables (sessions, accounts, verification — generated by its CLI)

## Phase 2 — Landing page (static, no backend)

Build the page top-to-bottom matching the mockup vibe. Modal opens but submits are stubbed.

Section order: Hero → Hook → How It Works (5 steps) → Packages (Legacy + Heirloom) → Trust → About → FAQ → Footer CTA → minimal footer.

- Mobile-first responsive
- Subtle scroll-reveal fade-ups, gold gradient dividers between sections
- Two CTAs ("Reserve Your Time Today" and "Have questions? We'd love to chat.") both open the same modal with different titles
- FAQ accordion (shadcn Accordion)
- All copy verbatim from the Copy Package PDF
- Booking modal shell: 3 steps + confirmation screen, progress dots, validation on step 1, but slot picker uses placeholder data and Confirm just shows the success screen — no API calls yet

## Phase 3 — Google Calendar integration

The hardest piece. Owner provides OAuth credentials.

- OAuth 2.0 setup against `peaklegacyvideos@gmail.com`
- Refresh token stored server-side (env var or DB row, encrypted)
- `GET /api/availability?date=YYYY-MM-DD` — returns array of free 30-min slots between 9:00 AM and 4:30 PM PT for that date, after subtracting busy times from GCal
- `POST /api/book` — creates a GCal event with lead details (title, attendee, description with package + notes)
- Wire the modal calendar to `/api/availability` and the confirm button to `/api/book`

## Phase 4 — Booking submission, emails, pixel

The full conversion path triggered by `POST /api/book`.

- Insert `lead` row + `booking` row in a transaction (or upsert lead by email)
- Create the GCal event (Phase 3)
- Send confirmation email to lead via Gmail SMTP (template from spec PDF)
- Send notification email to `peaklegacyvideos@gmail.com` via Gmail SMTP
- Set `booking_status = 'Booked'` on the lead
- Return success → modal shows confirmation screen
- Fire Meta Pixel `Lead` event client-side after the success response
- Capture and persist UTM params from the URL
- Install Meta Pixel base script in root layout (PageView fires automatically)

## Phase 5 — Owner auth + CRM dashboard

Owner-facing. Behind BetterAuth.

- BetterAuth wired, single owner account seeded
- `/admin` (or similar) route group, gated by middleware
- Login page
- Dashboard view:
  - List of all leads with sortable columns: name, email, package, booking status, created_at
  - Lead detail view: all fields, notes, booking date if booked, email sequence status
  - Manual "Mark as Booked" / "Mark as Not Booked" toggle (stops or restarts sequence)
- Simple stats at top: new leads (last 7d), booked calls (last 7d), open sequences

## Phase 6 — Email sequence engine

5-email follow-up drip for non-bookers. Auto-stops on booking.

- Sequence trigger: any lead form submission that isn't immediately followed by a booking schedules 5 `email_jobs` rows at +0min, +1d, +3d, +6d, +14d
- Booking confirmation cancels all pending jobs for that lead
- Owner manually marking a lead as Booked also cancels pending jobs
- A scheduled worker (Vercel Cron or Railway cron) runs every ~5 minutes, finds due jobs, sends via Gmail SMTP, marks `sent_at`, retries on failure with backoff
- Email templates for all 5 emails, copy verbatim from the Copy Package PDF
- (Open/click tracking is not available with Gmail SMTP. Conversions are measured at the booking-submit boundary via Meta Pixel.)

## Phase 7 — Polish, perf, launch checklist

The spec's developer checklist, end-to-end.

- Lighthouse mobile score, target <3s LCP
- Image compression for any assets the client provides (logos, photos)
- SSL — handled by Vercel
- 404, error boundaries
- Robots/SEO basics — noindex during dev, allow at launch
- Verify Meta Pixel firing in Meta Events Manager
- End-to-end smoke test: form submit with no booking → 5 emails fire on schedule; form submit + booking → GCal event + 2 emails + no sequence
- Owner walkthrough of the CRM
- Hand off OAuth client setup steps to the owner

## Out of scope (intentionally)

- Payment processing (Wave handled manually)
- Lead-facing accounts or login
- Rescheduling UI (leads reply to email)
- Admin role hierarchy (single owner)
- Multi-package or custom package configurator
